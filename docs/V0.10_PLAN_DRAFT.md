## Item 1 — Status-led read path (THE unlocking primitive)

**What:** Typed temporal status on every read, supersedes-chain resolution, and
status-aware ranking. The continuity packet and claim cards are host projections over this;
build it first (nuron reorder, accepted).

- `RecallResult.status: active | superseded | disputed | aged` as a TYPED field (today:
  prose flags in `why_retrieved` — "prose-first stamps are how verdict-ranked-5th
  survived").
- `superseded_by` / `disputed_with` rid fields populated from existing link + conflict
  machinery.
- `resolve_current(rid)` → head of the supersedes chain (walk existing Supersedes links;
  cycle-rejected at write). New, small.
- `recall(..., include_superseded=false)` — **default-on exclusion** of superseded records
  (positive-capability flag naming per nuron; behavior change gated to this minor bump,
  loud CHANGELOG, audit/list paths keep full history by default).
- Status-aware demotion inside composite scoring (see Item 2 — same code path).

**API notes (consumer review R3, accepted):** the status enum is `#[non_exhaustive]`
(expired/retracted/unresolved reserved for v0.11+ without a breaking change);
`disputed_with` is PLURAL (disputes are many-to-many; `superseded_by` stays singular —
chain head); `resolve_current(rid)` returns `(rid, status)` so a disputed chain head is
visible at zero extra cost.

**Item 1b — coverage-reporting absence (consumer review G1, was a trace without a
feature):** `recall_with_response` gains a typed `SearchCoverage` payload — namespaces
searched, kinds searched, threshold τ, and the no-matching-record vs below-threshold
distinction. Size S; proof = T8.

**Item 1c — continuity-packet projection (consumer review G2, made explicit):**
`session_digest` upgrade so T10 is passable: decisions-IN-FORCE (resolve_current applied
to the digest's decision list), agenda integration (active objective / open questions),
last action+result, and what-changed-since-T (records + status transitions after T).
This was implicitly required by T10; now a named sub-scope. Size folded into Item 1's M.

**Proof:** traces T1 (supersede-then-recall, hard-zero stale-at-k1 from day one), T2
(chain-head resolution), T5 (disputed-not-dropped), T8 (coverage), T10 (packet
correctness).
**Size:** M. **Consumer lens pre-answered:** typed-before-score yes; no prose parsing
needed for packet/cards; include_superseded naming adopted; laundering checks at write time.

**Docs (consumer review R5):** a documented decision rule — `correct()` = the RECORD was
wrong (same fact, fixed content, rid-stable re-embed); supersede = the WORLD changed (new
record + edge, old record stays as history) — plus a typed hint in the correction error
message so agents don't blur T1/T2 semantics.

## Item 2 — Composite-score rebalance via learned linear weights (Pranab's learning layer, part 1)

**What:** The measured defect (two independent consumers): recency+importance additive
boosts produce scores >1.0 and bury semantically-relevant low-importance memories
(q38-class: 0/3 recall even with a better embedder and all candidates scored). Instead of
hand-retuning: fit linear ranking weights on the golden-query set through the **existing**
`load_learned_weights` path (recall already loads per-DB weights every query).

- Hand-rolled logistic + PAV isotonic **in-engine, zero new deps** (<200 lines each;
  unit-tested against offline sklearn goldens). No linfa/smartcore.
- Fitted weights ship as new DEFAULTS only after beating shipped heuristics on **held-out**
  golden queries (trace T13); per-DB learning personalizes after a sample-size floor.
- All learned outputs stamped `basis=learned(model-vX)`; versioned artifacts; replay pinned
  to model epoch. Anti-laundering applies to models.
- Includes the IDF-weighted keyword boost (measured: "project" matching half the corpus
  boosts as hard as a discriminative token).

**Proof:** T13 + golden-suite MRR/recall gates + T12 stale-metric computed in CI.
**Size:** M.

## Item 3 — RID-stable correction with re-embed (sol item 4)

**What:** Lift the v0.9.3 `CorrectionRequiresReembed` refusal: embed new text, tombstone
old vector, reinsert same rid via the existing HNSW tombstone/resurrect + delta primitives
(no cold rebuild — verified cheap in the v0.9.3 debate). Preserves rid, created_at, links,
revision history, replication payload.

**Proof:** old-topic/new-topic retrieval flip; phase fault-injection + kill/reopen (every
visible state wholly old or wholly new); T4 same-session correction visibility (catches
scoring-cache staleness — zero coverage today).
**Size:** M.

## Item 4 — Typed-record chokepoints (consumer spec, engine half)

**What:** The anti-laundering write gate. `source` (user|inference|document|system) and
`metadata.kind` already exist with a v32 generated column; add (a) `confidence_basis`
(observation | confirmation | verification | inference | learned(model-vX)) as a typed
field, (b) the WRITE-TIME refusal: a record deriving from an inference-source provenance
ref cannot claim kind=fact/observation (typed error, same pattern as the v0.9.3 gate),
(c) the INTERNAL-CONSISTENCY matrix (consumer review R4 — closes laundering-by-OMISSION,
where the caller simply doesn't cite provenance): `source=inference ∧
confidence_basis=observation` → typed refusal; `source=inference ∧ kind=fact/observation`
without explicit override → refusal or forced kind=inference. Caller-declared fields can't
be externally verified, but internal consistency can be,
(d) idempotency keys (caller-supplied, uniqueness constraint, deterministic retry) with the
T7 assertion: retries must NOT inflate certainty.

**Proof:** T6 (anti-laundering), T7 (repetition≠corroboration), T3 (status freshness).
**Size:** M.

## Item 5 — Operational safety contract (sol item 5, unchanged scope)

**What:** Exclusive process ownership (Windows-aware design note first; documented
read-only escape), POISONED engine state after internal panic, typed errors preserved
through PyO3 (today flattened to RuntimeError strings — the #60 -32602 root class), and a
read-only `diagnostics()` snapshot (poison state, capabilities, delta fill, backpressure,
pending oplog, generation, and — consumer review R6 — the learned-weight MODEL EPOCH, so a
host can render "ranking model updated since your last session" instead of silently
shifting rankings).

**Proof:** two-process CI on Linux+Windows; injected-panic → EnginePoisoned; Python asserts
error kind/fields survive the boundary.
**Size:** M.

## Item 6 — Reliability gate: T1–T13 as release-blocking labeled traces (sol item 6 × nuron wishlist)

**What:** The consumer-metric CI. Deterministic labeled traces for supersede/stale/scope/
absence/packet/interruption behavior (full T1–T13 list in shared memory, rid 019f5e30),
kill-mid-txn crash harness + `quick_check`, verified online backup/restore, scale/startup
budgets (100K, then 1M) as assertions. Interruption traces wire the EXISTING
SuppressionCause/SurfaceOutcome types into measurement; the bandit censored-feedback rule
(exploration inside the SurfaceRateLimiter budget; rate_limited suppressions excluded from
bandit updates) is encoded as a trace.

**Thresholds:** T1-class stale-at-k1 = hard zero from day one; T3-class = monitored one
release, then ratio-gated with a sample-size floor (X, N picked from monitoring data).
**Size:** M–L (the largest item; it gates everything else's honesty).
